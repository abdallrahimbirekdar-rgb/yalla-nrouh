Data saver, persistent booking drafts, local route recording, dark/system theme, opt-in local alerts, manual SMS composer, and local demo fare settings are available. The application is still a single-device demo; booking synchronization, automatic SMS, remote driver updates, and local payment providers are not connected. Android release builds target Android 7+ and publish separate ARM64/ARM32 APKs. Actual APK sizes are measured after building; physical-device testing remains required. Native maps no longer require a Google Maps key.

# يلا نروح — Yalla Nrouh

مشروع تطبيق أصلي لأندرويد وآيفون ونسخة ويب، بالعربية والإنكليزية. الإصدار **0.5.0 تجربة محلية**: لا يطلب سيارة فعلية ولا يسجل حسابات حقيقية. يمكنه قراءة موقع الجهاز في المقدمة بعد ضغط زر الموقع والموافقة على إذن النظام.

## التصميم الجديد

واجهة بسيطة مع خريطة اختيارية، وخط Cairo، وشعار معتمد مصغّر، وحجز من الأسفل وقائمة للأدوات. تدعم المظهر الفاتح والمظلم ومظهر الجهاز.

## ما يعمل الآن

- اختيار محافظة الانطلاق من المحافظات السورية الأربع عشرة، وعناوين الانطلاق والوصول، ورحلة داخل المدينة أو بين المدن.
- الفئات الست المطلوبة: كلاسيك فوري، كومفورت مكيفة فوري، تكسي عمومي أصفر، قمة الرفاهية، يالله سيدات كلاسيك، يالله سيدات كومفورت.
- مراجعة الطلب قبل تأكيده، ومنع وجود طلبين نشطين في الوقت نفسه.
- اعتماد سائق تجريبي من الإدارة ثم تشغيل استقبال الطلبات.
- قبول الطلب، تسجيل الوصول، التحقق من رمز بدء الرحلة، بدء الرحلة وإنهاؤها.
- إلغاء قبل بدء الرحلة، وتقييم واحد بعد اكتمالها، وسجل الرحلات.
- اختيار نقاط الرحلة على خريطة الهاتف، أو باستخدام GPS عند الطلب، أو إدخال الإحداثيات يدويًا. خرائط OpenStreetMap على الهاتف والمتصفح دون مفتاح Google.
- عميل بحث بالعناوين جاهز للربط بخادم؛ لا توجد خدمة بحث منشورة أو متصلة افتراضيًا.
- شاشة حالة الخدمات في الإدارة لتمييز الجاهز عن غير المرتبط.
- حفظ محلي على الجهاز مع التحقق من البيانات عند الاستعادة وإيقاف استقبال الطلبات تلقائيًا بعد إعادة التشغيل.
- مشاركة ملخص نصي تجريبي عبر قائمة مشاركة النظام. **هذه ليست مشاركة موقع أو رابط متابعة مباشر.**
- واجهة عربية من اليمين إلى اليسار وواجهة إنكليزية من اليسار إلى اليمين.

شاشات الراكب والسائق والإدارة مجتمعة في تطبيق تجريبي واحد لاختبار تدفق الرحلة. عند الإطلاق تُفصل صلاحياتها على الخادم، ويُجهز تطبيق السائق ولوحة الإدارة بصورة مستقلة. فتح شاشة الإدارة هنا ليس نظام صلاحيات فعليًا.

## التشغيل

المتطلبات: Node.js 22.13 أو أحدث وnpm. استُخدم قالب Expo SDK 55 الرسمي مع إصداراته المتوافقة.

```bash
npm ci
npm start
```

للمعاينة عبر المتصفح:

```bash
npm run web
```

يمكن استخدام Expo Go المتوافق مع SDK 55، أو إنشاء development build. لا تفترض توافق أحدث Expo Go مع هذا الإصدار؛ راجع توافق SDK عند التجربة.

لإنشاء ملف Android APK داخلي بعد إعداد حساب Expo ومعرف مشروعه:

```bash
npx eas-cli@latest build --platform android --profile preview
```

لبناء iOS داخليًا، يجب إعداد حساب Apple Developer والتوقيع وتسجيل أجهزة الاختبار. أُنتج ملف APK اختبار للإصدار 0.3.0 محليًا لأجهزة ARM64 بتاريخ 3 نوفمبر 2026، وفُحص توقيعه واحتواؤه على حزمة التطبيق وتوافق توقيعه مع تحديث الإصدار السابق. لم يُختبر على هاتف فعلي أو يُرفع إلى متجر. راجع `docs/ANDROID_TESTING.md`. المعرف `com.yallanrouh.demo` مؤقت للتجربة.

## تجربة كاملة في بضع خطوات

1. افتح «الإدارة» ثم «اعتماد السائق التجريبي».
2. افتح «السائق» ثم شغّل استقبال الطلبات.
3. افتح «الراكب»، وحدد العناوين والفئة وراجع الطلب وأكده.
4. افتح «السائق» واقبل الطلب وسجل الوصول.
5. افتح تفاصيل الرحلة من شاشة الراكب واحفظ رمز البدء الظاهر فيها.
6. ارجع للسائق وأدخل الرمز وابدأ الرحلة، ثم أنهها.
7. افتح «السجل» ثم تفاصيل الرحلة، وأضف التقييم.
8. أعد فتح التطبيق للتحقق من استعادة السجل. تبقى حالة السائق «غير متاح» حتى تفعيلها مجددًا.

## العمل المتبقي قبل التشغيل الحقيقي

1. خادم وحسابات موثقة وأدوار فعلية للراكب والسائق والإدارة، مع تخزين آمن وإدارة جلسات.
2. تحقق هاتفي عبر مزود يمكنه إيصال الرموز إلى الأرقام السورية، وتجربة التسليم عمليًا.
3. ربط خادم البحث بالعناوين، واختبار الخرائط وGPS على أجهزة فعلية، وربط مواقع السائقين الحية بالخادم. التسجيل المحلي والتقدير الحاليان تجريبيان.
4. تسعير معتمد لكل مدينة وفئة، وموافقة الراكب على عرض سعر له مدة صلاحية.
5. توزيع الطلبات من الخادم مع منع قبول عدة سائقين للطلب نفسه وإعادة المحاولة وانتهاء مهلة العروض.
6. التحقق من السائق والسيارة ومستنداتهما، وتصنيف السيارات وفق معايير يقرّها المشروع، وتأكيد تفاصيل فئتي السيدات.
7. رمز بدء مولّد ومتحقق منه على الخادم، مع حدود للمحاولات. الرمز المحلي الحالي تجريبي وليس إجراء حماية إنتاجيًا.
8. إشعارات فعلية، ومشاركة متابعة آمنة، ودعم وشكاوى وسياسة إلغاء وخصوصية وحذف حساب.
9. متطلبات تشغيل الخدمة محليًا، واختبار أجهزة وشبكات وتوقيع ونشر المتاجر.

لا تُستخدم المعلومات المحلية التجريبية كأساس للتسعير أو المحاسبة. لا توجد في هذه النسخة أرباح أو عمولات محسوبة، أو تتبع مباشر، أو اتصال بسائق حقيقي، أو حسابات فعلية.

## بنية الملفات

- `src/app/`: صفحات Expo Router.
- `src/domain.ts`: الأنواع وقواعد انتقال الرحلات والتحقق من البيانات.
- `src/context.tsx`: حالة التطبيق واستعادة البيانات وطابور الحفظ.
- `src/storage.ts`: تخزين محلي باستخدام Expo SQLite على الهاتف.
- `src/storage.web.ts`: تخزين معاينة المتصفح.
- `src/ui.tsx`: مكونات الواجهة وتغيير اتجاه النص.
- `src/map/`: خريطة الهاتف وبديل معاينة المتصفح.
- `src/api.ts`: عميل البحث بالعناوين والتحقق من الاستجابة.
- `src/geo.ts`: تحقق الإحداثيات ودعم الأرقام العربية.
- `app.config.ts`: إعداد إذن الموقع في المقدمة.
- `tests/domain.test.mjs`: اختبارات قواعد الرحلات.

لا يحتوي المشروع على مفاتيح خاصة أو بيانات دخول أو حسابات مستخدمين حقيقية.
